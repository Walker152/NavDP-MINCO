# NavDP–MINCO 实验软件架构设计

## 1. 设计结论

本轮采用独立的 `experiments` Python 包承载实验工程。真实 NavDP、MINCO 和 Isaac Lab 只通过后端协议接入；默认交付 deterministic mock 后端，用于在不加载模型、不启动 Isaac Sim 的条件下验证场景、指标、记录、校验、配对分析、断点续跑和报告生成的闭环。

这是对 01/02/03 文档的工程化交集：01 的 EXP-00～08 是结果组织轴，02 的 schema 和指标是数据契约，03 的 manifest、suite、run 状态机和 resume 是执行契约。用户要求优先于原提示词中的建议路径，所有新增实验代码、配置、测试和示例均放在 `experiments/`；实际结果默认放在仓库根目录 `results/<suite_id>/`。

## 2. 范围与明确假设

- 本地禁止启动 Isaac Sim、Isaac Lab、NavDP 服务和 CUDA 推理，只运行 mock、单元测试和静态导入测试。
- 不修改现有算法参数、四个 eval 入口、C++ MINCO 或已有输出；真实接入作为后续小范围适配工作。
- 本轮实现可执行的实验骨架及关键指标，不承诺在无真实数据时生成具有科研结论的图表。报告必须将 mock 数据标为 `SIMULATED`，不得把它写成算法效果。
- `episode_uid` 与 variant/run 无关，以保证 RAW/COLD/HOT 可配对；`plan_uid` 在 run 内唯一。
- OOB、NaN 和 Inf ESDF 查询均按不安全；空值保留 NaN，不写 0。
- 结果目录采用 01 的“实验目的/场景/方法/种子/run”层次，但根目录按用户要求改为 `results/`。

## 3. 包结构与职责

```text
experiments/
├── analyzers/      # 几何、安全、时域指标；输出校验；run/paired/suite 报告
├── cli/            # python -m 可调用入口
├── configs/        # smoke/pilot/full 配置样例
├── core/           # 类型、schema、路径、异常；不依赖仿真
├── designers/      # scenario manifest 与 suite run 展开
├── docs/           # 使用、接入、测试与交付说明
├── orchestrators/  # 状态机、resume、后端调用和分析流水线
├── recorders/      # CSV/NPZ 异步写入和 run 生命周期
├── simulators/     # ExperimentBackend 协议和 deterministic mock
└── tests/          # 不启动仿真的单元/集成测试
```

各模块仅通过 dataclass、字典 schema 和 `ExperimentBackend` 协议通信。分析器不导入 Isaac/torch；模拟器不负责统计；编排器不计算指标；记录器不作科研判断。

## 4. 数据流

```text
suite.json + scenarios.json
        ↓ designers 校验并展开 RunSpec
orchestrator → backend.run(run_spec, sink)
                         ↓
                  RunRecorder 原子写入
                         ↓
 episode/plan/candidate/control/timing/events CSV + trace NPZ
                         ↓
             validator（失败则 run 不可 COMPLETE）
                         ↓
          run analyzer → paired analyzer → suite analyzer
                         ↓
 results/<suite>/reports/EXP-xx/... + suite_report.md
```

真实后端接入时，eval 循环只需在“已通过 stale 检查并准备发布”处提交 plan，在 `env.step` 前提交 control，在 episode 结束时提交 episode。HOLD_LAST 记录事件但不得增加 `minco_ok_count`；stale plan 不得写入 `plan_metrics.csv`。

## 5. 输出与状态

单 run 路径：

```text
results/<suite_id>/experiments/<experiment_id>/<scene_label>/
  <variant>/<seed>/<run_id>/
```

包含 `run_config.json`、`run_status.json`、六张核心 CSV、`traces/`、`analysis/` 和 `logs/`。状态按 `CREATED → RUNNING → SIMULATION_COMPLETE → VALIDATING → COMPLETE` 转移；异常进入 `FAILED`，中断进入 `INTERRUPTED`。JSON 和 NPZ 使用临时文件加原子替换。`--resume` 只跳过经重新校验仍有效的 COMPLETE run。

## 6. 错误处理与安全语义

- 配置、manifest、schema 和状态转移错误使用显式领域异常，CLI 返回非零退出码。
- CSV 多余字段立即报错，缺失字段补空；writer 线程异常在下一次 submit/close 重新抛出。
- 校验器检查 schema、run 完整性、主键、episode 终止、variant 字段语义和模拟标记。
- mock 后端不会访问网络、GPU 或仿真；真实后端未配置时明确拒绝运行，不隐式启动任何重资源进程。
- 报告只陈述观测值；mock 报告顶部显示“仅用于工具链验收”。

## 7. 测试设计

测试遵循 RED–GREEN：先验证缺失行为会失败，再写最小实现。覆盖直线/圆弧/退化路径、ESDF 插值和 OOB、MINCO 时间加权统计、轨迹 shift、点到折线、标签边界、异步写入、原子 NPZ、稳定 UID、manifest/suite 校验、resume、HOLD/stale 语义、配置不匹配拒绝配对，以及 mock 端到端生成最小报告。

所有验证命令在 `conda activate navdp` 后运行；不调用 `conda activate isaaclab`，仅在接入文档中给出未来真实运行命令。

## 8. 后续真实接入边界

后续新增 `IsaacNavDPBackend` 时应最小改造 `eval_pointgoal_wheeled.py`：透传 headless/输出/manifest/seed 参数，将 monitor hook 放到已有 generation/stale/HOLD/STOP 语义之后，并保持 `num_envs=1`。C++ 热启动 Preview/Commit 是独立高风险子项目：只有通过 C++、Python ESDF、stale 检查且真正发布给 MPC 的 proposal 才能 commit；本轮不在缺少真实仿真验证时修改它。
