# NavDP 滚动规划与论文展示产物设计

## 目标

把现有“单次局部 MINCO 输出”静态实验升级为可复现的确定性滚动规划实验，并生成研究论文可直接采用的静态图、同步动图、数据、双语 caption 与证据收据。实验必须明确区分输入 guide、Legacy MINCO 和 Safe-corridor MINCO，不得把输入折线或单次局部规划冒充完整执行轨迹。

## 已确认的实验语义

### 完整路线

静态实验采用滚动局部规划。每个周期根据当前状态截取局部 guide，调用一次 MINCO，执行轨迹的固定前缀，然后把该前缀末端的位置、速度、加速度、yaw 与 yaw rate 传给下一周期，直至到达最终目标或触发明确的失败终止条件。

每轮候选规划和实际执行前缀均独立保存；论文中的“完整轨迹”只能由实际执行前缀累计得到。单轮候选轨迹以低透明度规划历史显示，不能计作全程执行结果。

### 三路比较

每个场景使用相同的 guide、初值、障碍状态、规划频率、执行策略和随机种子，比较：

1. 输入 guide：非可执行参考路径；
2. Legacy MINCO：不加入安全走廊约束的滚动优化完整轨迹；
3. Safe-corridor MINCO：加入安全走廊约束的滚动优化完整轨迹。

真实 trace 若包含 `raw_path_xyz`，则额外显示“NavDP 原始候选轨迹”。Synthetic 场景不存在原始候选轨迹时不得人工伪造。

### 动态障碍

本地确定性动态实验与 IsaacLab 验证分层执行。本地实验中，障碍物按固定、可复现的时间轨迹运动；每个规划周期只使用当前观测位置更新占据栅格、ESDF 与安全走廊，不加入当前系统没有提供的未来轨迹预测。IsaacLab 用于独立验证真实控制、碰撞与到达情况。

## 场景矩阵

必选场景包括：

- 无障碍基准；
- 稀疏静态障碍；
- 密集静态障碍；
- 窄通道；
- 会导致 Legacy 畸形绕行或越界趋势的极端静态障碍；
- 动态横穿；
- 动态迎面；
- 动态遮挡或突然出现。

初值实验严格采用单因素扫描，分别改变初始位置、速度、加速度、yaw 与 yaw rate，其他条件保持不变。初值扫描需要同时覆盖 Legacy 和 Safe-corridor，报告完整路线而非单周期输出。

## 组件与数据流

### 场景定义

场景层提供世界边界、静态障碍、动态障碍轨迹、完整 guide、最终目标状态、初始状态、规划周期与随机种子。动态场景在任一给定仿真时刻必须确定性地产生同一障碍状态。

### 滚动规划引擎

滚动引擎负责局部 guide 提取、MINCO 调用、轨迹前缀执行、状态传递、目标判定与失败判定。其输出由“全程摘要”和“周期记录”组成。周期记录至少包含：

- 周期编号与单调时间；
- 输入位置、速度、加速度、yaw、yaw rate；
- 当前局部 guide、局部目标与最终目标；
- 稀疏 waypoint 与 MINCO 全候选轨迹；
- 实际执行前缀及末状态；
- 安全走廊胶囊段、半径、最小净空和生成状态；
- 当前静态/动态障碍状态；
- 优化状态、耗时、迭代数、惩罚项和验证结果。

引擎必须设置最大周期数、最大模拟时间、停滞窗口、碰撞阈值和目标容差。终止状态固定区分到达目标、碰撞、优化失败、停滞、超周期和超时。

### 可视化层

所有静态图和动图使用固定编码：

- 输入 guide：灰色点划线；
- Legacy MINCO：橙色虚线；
- Safe-corridor MINCO：蓝色实线；
- 累计执行轨迹：加粗；
- 单轮候选规划：同色低透明度细线；
- 安全走廊：蓝色半透明胶囊区域，边界可见；
- 初始状态：绿色；
- 最终目标：紫色；
- 危险或失败：红色。

每张 XY 图都必须使用等比例坐标，并显式绘制：初始 yaw 箭头、沿完整轨迹等弧长抽样的机器人方位角箭头、当前 yaw 粗箭头、速度方向细箭头和目标 yaw 空心箭头。目标 yaw 未提供时标注 `N/A`，不得推测。动态障碍使用红色箭头表示速度方向和大小。

动图同时显示当前状态、局部目标、最终目标、当前候选规划、累计执行轨迹、当前安全走廊、障碍位置与运动方向。状态框显示 `x/y`、yaw 的角度与弧度、速度、加速度、yaw rate、规划周期、模拟时间、净空、规划状态和终止状态。失败动画停留在失败帧并标红。

Yaw 时序图采用展开后的角度，避免 `-pi/pi` 跳变，并在关键时刻配合 XY 姿态箭头。朝向箭头与速度方向箭头在图例中保持不同视觉编码。

每次运行额外生成：

```text
results/<run_id>/paper_showcase/
├── 01_trajectory_optimization/
├── 02_safe_corridor/
│   ├── sparse_obstacles/
│   ├── dense_obstacles/
│   ├── narrow_passage/
│   └── malformed_detour/
├── 03_initial_state/
│   ├── initial_position/
│   ├── initial_velocity/
│   ├── initial_acceleration/
│   ├── initial_yaw/
│   └── initial_yaw_rate/
├── 04_dynamic_obstacles/
│   ├── crossing/
│   ├── head_on/
│   └── sudden_appearance/
├── 05_extreme_cases/
├── 06_aggregate_figures/

```

每个场景包至少包含：

- 三栏完整轨迹图；
- 三路叠加对比图及必要的局部放大图；
- 安全走廊几何图；
- 三路同步 GIF；
- 300 DPI PNG 和矢量 PDF；
- backing CSV、指标 JSON、运行/场景 manifest；
- 中英文论文 caption；
- artifact receipt 与 validation 结果。

`README_成果索引.md` 直接说明每项产物的位置、建议查看顺序、图能够支持的结论和证据限制。

## 比较公平性与极端案例选择

Legacy 与 Safe-corridor 的比较必须共享所有非方法变量。绘图必须共享坐标范围、采样规则和指标定义，禁止通过各面板独立缩放制造视觉差异。

极端案例从标定集合按预先固定的轨迹畸变、安全间距、失败状态和安全走廊改善评分选取；完成选择后锁定测试集合并报告全部结果。不得仅人工挑选有利结果。`syn_dense_short` 只作为短距离/密集采样边界案例，不再作为安全走廊效果代表案例，因为其无障碍且当前两种优化结果相同。

## 指标与 caption

全程指标至少包括到达率、碰撞、最终误差、完整路径长度、相对 guide 长度、总耗时、规划周期数、重规划失败数、停滞、最小静态净空、最小动态间距、速度/加速度/jerk/yaw-rate 违反比例及周期级求解时延。

Caption 必须从 backing data 生成，并包含方法、比较键、分母、单位、样本量、结果解释、失败状态、缺失数据和局限性。动态本地实验明确标为 `SIMULATED`，IsaacLab 实验在真实执行和证据校验完成后才可标为 `REAL_VALIDATED`。

## 验证与失败关闭

测试按以下层级执行：

1. 滚动状态传递、局部 guide 选择、终止状态和动态障碍确定性的单元测试；
2. 小型 synthetic 场景的 Legacy/Safe 全程集成测试；
3. 图、GIF、CSV、caption、manifest 和 receipt 的 schema 与篡改测试；
4. 一键静态工作流端到端测试；
5. 本地完整实验与代表性产物人工检查；
6. IsaacLab 授权运行后的独立验证。

任何缺失周期数据、非单调时间、状态传递不一致、未到终点却标记成功、图表与 backing data 不一致、媒体无法解码、收据哈希错误或 caption 缺字段，都必须使该场景或整个展示阶段失败关闭。

## 验收条件

- 每个预设场景都有完整静态图、同步三路动图、数据、caption 和校验结果；
- 静态图与动图均包含清晰的机器人方位角箭头；
- Safe-corridor 场景实际绘制走廊胶囊，而非只报告诊断数字；
- 初值在图面、数据和 caption 中均显式呈现；
- 所有折线场景运行到最终目标或明确记录失败；
- `syn_dense_short` 的语义被正确标注且不再承担无效的走廊效果证明；
- 一键脚本从标定、实验、分析到 `paper_showcase` 和总收据可完整执行；
- 本地动态证据与 IsaacLab 真实验证保持清晰边界。
